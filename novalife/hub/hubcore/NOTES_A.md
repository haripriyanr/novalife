# Module A notes (ascon, tag_block, polar, iwt)

Build/run (own sources only, independent of modules B/C): `tests/mybuild.sh ascon tag_block polar iwt`
then `./build/test_<name>` from `hubcore/`.  `make build/test_<name>` works once every file in `src/`
compiles.  Golden data: `tests/gen_*.py` (Python oracle) -> `tests/golden/*`; `src/polar_tables.h`
is generated by `tests/gen_polar.py` from `polar_codec.RELIABLE_INDICES`.

## Verified (all compare against golden data from the Python and fail on mismatch)
* **ascon**: all **1089/1089** official KATs (parsed from the LWC file in the C test) + 300 random
  AEAD cases (lengths 0..79 pt/ad), 200 `mac_truncated` (message up to 300 bytes, nbits 8..128, both the
  stack and malloc path), 100 `keystream` (up to 3000 bytes).
* **tag_block**: 300 `build` cases (bits and bytes forms; includes all-zero and all-ones fields), 1028
  `verify` cases: 300 intact accepted, 728 rejected (a random single flipped bit x300, wrong key x300,
  every one of the 128 bit positions flipped once x128); decoded fields, tag and expected tag equal Python.
  NOTE: the MAC input encodes the header as 11 bytes (1+2+8), although the Python constant
  `HEADER_BYTES` says 10; C follows the Python behaviour (length byte 11).
* **polar**: encode 500/500 bit-exact (zero, all-one, all 128 unit vectors, random).  SCL L=8 decode:
  **470 cases, info bits identical in 470/470 and path metric bit-identical in 470/470** (clean, Eb/N0
  30..0 dB; 161 of them are cases where Python itself decodes wrongly, so errors are reproduced, not
  only successes; 60 integer-LLR/erasure cases and 30 equal-magnitude-LLR tie-stress cases).
* **iwt**: 53 images (2x2 ... 512x512, non-square, odd-half sizes like 66x34, int16 range, extremes,
  +-2^28, constant, alternating, ramp, full int32 range with wrap): LL/LH/HL/HH bit-exact vs
  `iwt2d_53`; `hc_iiwt2d_53` (clipped to 0..255) equals Python `iiwt2d_53`; `hc_iiwt2d_53_raw` is the
  exact unclipped inverse (round trip of the original int32 image, 53/53).
* Also run clean under `-fsanitize=address,undefined`.

## Bug found by the golden test (and fixed)
My first SCL port sorted the candidates also at frozen leaves.  Python reorders only at information
leaves; at frozen leaves the path order is untouched, and that changes tie-breaking later (5/470
cases differed, all in tie-heavy integer-LLR cases).  Fixed; the mutation list includes it.

## Mutation checks (`tests/mutation_check_A.sh`: 24 mutations on a scratch copy, 24/24 caught)
Ascon (rotation, IV, padding byte, domain separator, round count, MAC domain, stream nonce),
tag_block (length byte, hub_id packing, verify-always-ok, field offset, bit order), polar (frozen-leaf
reorder, unstable tie-break, F=max, G sign, bit-1 metric inverted, argmin picks last, encoder one
stage short), iwt (truncating shift instead of floor, update +2->+1, missing edge replication,
missing clip, HL/HH swapped).  One initial mutation (`>` -> `>=` on the bit-1 metric) survived because
it is an equivalent mutant (adds fabs(0)); replaced by a real one.

## Speed of `hc_polar_scl_decode` (host x86-64, gcc -O2, machine shared with other agents)
~1 ms mean per codeword (0.97 ms, worst 1.7 ms) on an idle run; 2-4 ms when loaded; ASan build ~4 ms.
Memory: one malloc of 16 x 20.7 KB = 331 KB per call (freed before return).  Not measured on the A9.

## Design notes
* Floating point: `double` in the same operation order as Python.  G is written `b -/+ a` (identical
  to `b + (1-2u)*a`, no FMA contraction possible).  Decoding relies on IEEE doubles and no
  `-ffast-math`.
* iwt arithmetic wraps mod 2^32 like numpy int32; right shifts are floor shifts implemented without
  relying on implementation-defined signed `>>`.
* API: `hc_ascon_*`, `hc_tag_*` (block as `uint8[16]` packed MSB-first, or `uint8[128]` one bit per
  byte = Python array = polar info input), `hc_polar_*`, `hc_iwt2d_53` / `hc_iiwt2d_53[_raw]`
  (sub-bands passed as four separate `(h/2)x(w/2)` int32 arrays LL, LH, HL, HH).
