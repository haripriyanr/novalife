## What was wrong before

`vivado/ip_repo/perceptual_mask_core/perceptual_mask_core.v` was **not** the reference's
arithmetic and could not be checked against anything:

| | old core | reference |
|---|---|---|
| sample width | 8-bit unsigned pixel | signed sub-band coefficient |
| threshold | `var >= VAR_THRESHOLD>>8` with `VAR_THRESHOLD = 256` (a Q16.8 mix-up) | `var > 1` |
| ROI gate | `roi_flag`, i.e. **any** sample in ROI | `mean(tile_roi) < 0.5`, a **majority** test |
| variance | not exposed, so not observable | the number the mask is decided on |
| testbench | none | — |

The module docstring claimed "DSP48-accurate fixed-point local variance calculation: σ² = E[X²] −
E[X]² in Q16.8" while the expression `(sum_x2 >> 4) >= ((sum_x >> 4) * (sum_x >> 4)) +
(VAR_THRESHOLD >> 8)` compares a Q16.8 threshold (256) against a plain integer variance — the two
are not the same quantity.

## The contract (frozen)

`tools/stego_research/sims/perceptual_mask.mask_block_decision` — `generate_perceptual_mask`'s
per-tile decision, written without floats so hardware can be checked bit-exactly:

```
sum_x  = Σ x_i                 sum_x2 = Σ x_i^2
mean_x  = sum_x  // BLOCK      (floor, like Python's //)
mean_x2 = sum_x2 // BLOCK
var     = max(0, mean_x2 - mean_x^2)
mask    = 1  iff  (roi_count * 2 < BLOCK)  and  (var > VAR_THRESHOLD)
```

`roi_count * 2 < BLOCK` is exactly the reference's `np.mean(tile_roi) < 0.5`; `var > 1` is
`VAR_THRESHOLD = 1`. `compute_dsp48_variance` itself is unchanged: it is the reference that
already existed. `mask_block_decision` was added to the reference to state the *decision* the old
core got wrong.

Vectors: `tools/tag_reference/vectors/gen_mask_vectors.py` → `mask_in.mem`, `mask_roi.mem`,
`mask_exp_var.mem`, `mask_exp_mask.mem`, `mask_params.vh`, `mask_vectors.json`
(31 blocks of 16 signed samples + ROI bits).

## Verification (simulation, Icarus)

```
vivado/scripts/run_sim.sh perceptual_mask_core
  -> perceptual_mask_core_tb: PASS (31 vectors, 14 mask=1, 17 mask=0,
                                    bit-exact vs perceptual_mask.mask_block_decision)
```

The case set is built so every branch is reached, and the assertions in the generator fail if it
stops being so: `var == 0`, `var == 1` (must NOT embed), `var == 2` (must embed), the ROI majority
boundary (`roi_count` 7 embeds vs 8 protects on the same block), a negative sum that is not a
multiple of `BLOCK` where floor vs truncate division changes the answer (`[-7, -1×10, 0×5]`), its
positive twin, full-scale ±32767/−32768 blocks, and random blocks over several amplitude ranges
with random ROI counts.

**Mutation-tested** (the testbench must catch real defects, not just pass):

| mutation | errors |
|---|---|
| ROI gate back to the old any-ROI rule (`roi_cnt != 0`) | **16** |
| threshold `>` → `>=` (would embed the `var == 1` block) | **2** |
| `mean_x` floor shift `>>>` → logical shift `>>` (breaks negative sums) | **15** |

## Timing: the first design did not meet timing

The single-cycle version (accumulate → mean → square → subtract → clamp → compare → register) was
measured at **WNS −1.921 ns @100 MHz** — failing, worst path `sum_x_reg[20]`. It was split into two
compute cycles (`ST_MEAN` registers the two means; `ST_CALC` does the square/subtract/compare) and
the widths were narrowed to what the values can actually be (`mean_x` 17 bits, `mean_x2` 32 bits)
instead of a flat 48-bit datapath. That version meets timing.

## Real post-synthesis numbers

| Slice LUTs | Slice Regs | BRAM | DSP | WNS @100 MHz |
|---|---|---|---|---|
| **116 (0.66 %)** | **152 (0.43 %)** | **0** | **2 (2.5 %)** | **+2.054 ns — timing met** |

- Tool: `vivado v2026.1`; part `xc7z010clg400-1`; one 10 ns `create_clock`; `synth_1` only.
- Worst path: `mean_x_r` → `mask_out` (square → subtract → clamp → compare), +2.054 ns slack.
- The 2 DSPs are the two multipliers (`x*x` and `mean_x*mean_x`).
- Throughput: one block per `BLOCK + 2` cycles (16 samples in 18 cycles, steady state).
- `Bonded IOB > 100` in the report is an artifact of synthesising the core as top.

## Interface (changed — nothing integrates this core yet)

```
sample_in (signed 16) + roi_mask_in + valid_in   while ready_out
  -> after BLOCK samples and 2 cycles: var_out (32-bit) + mask_out + valid_out
```

Nothing in the repo instantiates this core yet (the tag pipeline is not built), so widening the
sample input from 8-bit pixels to signed sub-band coefficients is safe. Which mask the embedding
*path* uses (LL band vs LH/HL/HH) is part of the missing `qim_adaptive_embedder` contract and is
**not** decided here.
