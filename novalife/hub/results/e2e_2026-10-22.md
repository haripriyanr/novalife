# End-to-End System Integration & Cloud Relay Verification (2026-10-22)

## 1. Executive Summary

This document reports the end-to-end integration and verification of the NovaLife system across all four tiers:
1. **FPGA Hardware / PL Enclave**: XC7Z010 programmable logic running `tag_engine` (Ascon-128 AEAD, write-only key register, rate-limiting token bucket) clocked at 100 MHz.
2. **PS Firmware (FreeRTOS)**: ARM Cortex-A9 @ 667 MHz running `novalife_hub_fw` with `cloud_worker`, `image_worker`, and local HTTP server.
3. **Cloud Infrastructure (Supabase & Cloudflare)**: Verified TLS connection via ESP-AT v4.1.1.0; queue RPCs (`hub_device_claim`, `hub_device_complete`) with FCFS serialization, row-level security (RLS), and append-only audit trail (`verification_log`).
4. **Client Applications (Flutter)**: Multi-role mobile/desktop client (`patient_001`, `doctor_001`, `lab_tech_001`) with direct cloud queue integration for watermarking and verification.

All tests reported herein were measured live on physical hardware (xc7z010-clg400-1) and production database (`rtsduiqbgdiyygczivbl.supabase.co`).

## 5. Concurrent Multi-User FCFS Test

To verify race-condition resistance, strict serialization, and hardware exclusivity, authenticated users submitted verification jobs concurrently to the cloud queue.

### 5.1 Initial Concurrency Test & 120s Stall Investigation
In initial concurrent testing (e.g. jobs `6bbe05bc-f2bc-442a-a9da-f1d2bc054746` and `4da33aab-07f9-4d6d-8e4d-7a5dc0d5256e` at 11:15–11:20 UTC), the first job executed normally, but the second job was not claimed immediately: it stalled for ~2m17s until the Postgres 120s stale watchdog re-queued it (`attempts = 2`).

**Root Causes Identified**:
1. Passive receive mode (`AT+CIPRECVTYPE=4,1`) suppressed `+IPD` notifications in ESP-AT once triggered, causing replies to sit unread in the module buffer until timeouts expired.
2. In `esp_cipsend`, dropping the ring buffer upon finding `SEND OK` accidentally purged incoming `+IPD` frames that arrived before the acknowledgment.
3. Link closures by Cloudflare (TCP FIN) were not detected prior to transmission, causing subsequent completions to fail on closed links without retry.
4. The network task stack (8 KB) was marginal for deeply nested JSON buffers; increased to 16 KB (4096 words).

### 5.2 Real Measured Concurrency Results (6 Concurrent Jobs)

  - Clients submit jobs via HTTPS POST to Supabase.

  - No public IP, NAT port-forwarding, or dynamic DNS required on the hardware hub.

### 7.3 Embedded ARM Runtime Root Cause & Resolution
- **Issue**: Initial on-board `verify_image` evaluations on ARM Cortex-A9 returned `tag_ok=0` (reading pixel values `14 14 14 16` at row 0 instead of `16 16 16 16`), despite x86 C compilation passing bit-exact on the same image.
- **Root Cause**: `stb_image.h` defaulted to `STBI_THREAD_LOCAL` (`__thread` under GCC). On bare-metal / FreeRTOS where OS TLS registers are unmanaged, accessing `__thread` variables read uninitialized stack/BSS, causing `stbi__vertically_flip_on_load` to evaluate to true. The decoder was vertically flipping image scanlines on load (row 511 was read instead of row 0).
- **Resolution**: Defined `#define STBI_NO_THREAD_LOCALS` in `image_worker.c`. The decoder now uses the clean global default (`stbi__vertically_flip_on_load_global = 0`), producing bit-exact pixel rendering and 100% cryptographic tag recovery.
