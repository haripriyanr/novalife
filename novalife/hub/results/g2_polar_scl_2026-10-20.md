# G2 — polar SCL decoder, list size L=8 (2026-10-20)

**What:** `vivado/ip_repo/polar_scl_decoder/` — the RTL counterpart of the decoder the pipeline
actually uses (`polar_codec.polar_scl_decode`, L=8). Until today the RTL had SC only (list size 1).
**Level of evidence:** simulation (Icarus) + **post-synthesis** (Vivado 2026.1). No place-and-route,
no bitstream, no board.

## Contract

`tools/tag_reference/vectors/gen_polar_scl_vectors.py` implements SCL L=8 in exact integers **in the
hardware's schedule** (shared LLR scratch recomputed per path; all L paths' partial sums in one 8-bit
word per address; pruning as an in-place permutation; stable "first strict minimum" selection;
winner = first minimum path metric) and cross-checks it against the float reference:

| Check | Result |
|---|---|
| integer SCL (RTL schedule) == `polar_scl_decode(llr, 8)`, info bits **and** path metric | **24/24** |
| clean cases decode to the sent word | PASS |
| cases where SCL differs from SC (list size 1) | **11/24** (2 where SCL recovers the sent word and SC does not) |
| datapath | max internal \|llr\| 12775 (signed 16-bit), max pm 1460 (32-bit) |

Cases: 2 clean, 15 noisy at 4 amplitudes, 4 tiny-range random (ties everywhere — tests the stable
ordering), 4 full-range random (tests the width). Seed 20261020.

## Simulation (self-checking tb, info bits + path metric)

```
vivado/scripts/run_sim.sh polar_scl_decoder
polar_scl_decoder_tb: PASS (24 vectors, info bits + path metric bit-exact vs integer SCL L=8 contract; 2505200 cycles/codeword avg)
```

**Latency:** 2,505,200 cycles per codeword (measured in simulation) = **25.1 ms at 100 MHz**, 50.1 ms at
50 MHz. (SC was ~0.46 M.) A cycle count from simulation, not a board measurement.

### Mutation tests (each must FAIL)

| Mutation | Errors |
|---|---|
| unstable selection (`<` → `<=` in the candidate scan) | 7 |
| decision costs swapped (bit 1 charged the bit-0 cost) | 48 |
| leaf bit not forced during the permutation | 47 |
| winner = last minimum instead of first | 2 |

The two tie-breaking mutations are caught only because the tiny-range cases create ties; they are
what makes the vectors able to separate "an SCL" from "this SCL".

Script: `results/hw_core_synth_2026-10-20_scl/core_synth.tcl`
(`vivado -mode batch -source core_synth.tcl`, from that folder). The `.rpt` files are gitignored;
the numbers above are copied from `polar_scl_decoder/util.rpt` and `timing.rpt`.

About 900 of the registers are the candidate/selection state (16 × 32-bit candidate metrics,
8 × 32-bit kept metrics, 8 × 32-bit path metrics); narrowing pm to the measured need (11 bits for
these vectors, ~22 bits worst case) is a cheap area cut, not done.

## Not done / caveats

- Post-synthesis only. No place-and-route, no Fmax, no board run.
- 25 ms per decode is acceptable for `VERIFY_TAG` on one geometry; the software recovery tries up to
  1125 decodes per image (see `docs/improvement_review_2026-10-20.md` A3), which in this core would be
  ~28 s — the geometry search must stay on the PS or the core must get faster (process two paths per
  walk, or the standard lazy-copy schedule instead of a full walk per leaf).
- The output is the minimum-metric path only; MAC-aided list selection (check the tag on all 8
  paths) is a proposed decoder change, not built.
