# G1 — crop: the documented reason was wrong, and three real defects behind it

> **Date:** 2026-10-19. **State:** software only (Python reference). No hardware, no place-and-route,
> no real chat-app send. **Encoder unchanged** (see §6), so nothing that was measured about embedding
> is invalidated.

## 1. What was written down, and why it was wrong

`docs/algorithm.md` §4 and the G1 matrix said crop fails because *"the pilot grid is periodic, so a
crop can be detected but not located: one grid interval is another equally good grid"* — a
synchronisation limit, not a coding one.

Measured, that is not the reason. Two things are true instead:

- The **offset is not ambiguous**: for a pure crop the scale does not change while the size does, so
  `residual = received_ll − declared_ll × scale` is exactly how far the surviving content moved. The
  decoder already built that candidate. Crop was failing with the correct geometry *available*.
- The dominant limit is **capacity and taint**, not ambiguity: a 10% corner crop leaves region 0 with
  196 usable blocks where the codeword needs 256, and the cropped-away area is read as *data* rather
  than as *nothing*.

## 2. Three defects, each measured

### 2.1 One starved region aborted the whole read

`placement_map` raised `region 0: ran out of blocks while placing bit 206` when a region could not
place all 256 bits, and `read_regions` let that exception kill the entire attempt — even though the
other three regions each still carried the full codeword.

Fix: `placement_map(..., allow_erasures=True)` for the **decoder only**; a bit with no block becomes
`None`, and `read_regions` gives it **LLR 0.0** — an erasure, "no information here". The encoder still
refuses loudly, which is the correct answer there.

### 2.2 The crop geometry was known and ranked below decoys

The residual candidate existed but was not a priority candidate, so it competed for the 5 exact slots
against grid-equally-good candidates shifted by whole periods, which outrank it on the cheap score.

Fix: it is a priority candidate now — and **two** of them, because the residual is the *total* size
loss: it equals the content shift only when all of the loss is on one side.
`1.0 × residual` = corner crop, `0.5 × residual` = symmetric crop. Measured: symmetric 5% and 10%
crops were restored to within **0.0** of the original and still failed, because only `1.0 ×` was
offered and the true shift was half of it.

### 2.3 Placement depended on taint that only the decoder had

This is the one that mattered most, and it was invisible until the first two were fixed.

`read_regions` passed the full taint — including the *coverage* mask (which pixels were cropped away)
— into `placement_map`. But `placement_map` **skips tainted blocks**, so new decoder-only taint
shifts which block carries which bit and desynchronises the region. Measured on a 5% symmetric crop:
the restored pixels were **exact** (max |difference| 0.0 in the interior) and half of every region
still read wrong.

Fix: two masks with two different jobs, which must not be conflated.

| mask | what it is | who uses it |
|---|---|---|
| **placement taint** | ROI ∪ clipping level — what the encoder could see | `placement_map`, both sides |
| **erasure taint** | placement taint ∪ undercovered blocks (≥25% of the block's 16×16 pixel support cropped away) | zeroes the LLR, after placement |

Plus: the ROI threshold is now computed from **covered pixels only**. On a 40% corner crop the plain
rule put **0 usable blocks in every region**, including the one quadrant that was never touched,
because the 0-filled fill area dragged the mean down and grew the ROI over the whole frame.

## 4. The case that still fails, and its measured reason

Symmetric crops of 10% or more. Read at the *true* geometry, region by region:

```
symmetric 10%: avail [196, 274, 278, 370]  erased [60, 68, 78, 127]  ber [0.49, 0.5, 0.539, 0.0]
```

Region 3 reads **perfectly** (BER 0.0) with 127 of its 256 bits erased. Regions 1 and 2 read
**garbage** (BER ≈ 0.5) rather than erasures, so they poison the soft combine instead of abstaining.
Their placement still disagrees with the encoder's, because the restored frame's border — clamped
content that the encoder never had — is classified by the ROI differently from the original rows.

Why corner crops escape this: after a corner crop one quadrant is untouched, so it carries the whole
codeword alone (`decode_attempts` already tries single regions — region 3 alone recovers a 40% corner
crop). A symmetric crop touches every region, so there is no intact quadrant to fall back on.

**This needs a decision, not another patch.** The fix is to make the placement a pure function of
geometry and key — e.g. each bit assigned a fixed block, with unusable blocks punctured at the
encoder and erased at the decoder — instead of skipping tainted blocks during the scan. That changes
the **embedded output**, so per the project's own rule it needs the owner's call and a full
re-measure of the matrix, not a unilateral edit.

## 5. Cost — a real problem, being fixed

A crop recovery cost **95–200 s** in the reference. Profiled a 25% corner recovery before touching
anything (`cProfile`, 127.7 s total):

| step | cost |
|---|---|
| polar SCL decode | **74.6 s (58%)** — 1204 calls, 62 ms each |
| `placement_map` | **21.8 s (32%)** — of which `_block_keys` alone is 18.9 s |
| resample + 5/3 IWT + block reads | ~12 s (9%) |

**Pass 1, done 2026-10-19 (hub `ff25de6`): cache the two pure per-candidate costs.** All three caches
are pure functions, so the results are bit-identical by construction:

* `_block_keys(key, ll_shape, region)` — an Ascon-CTR keystream over every block of the universe,
  recomputed for every candidate and every fine offset although the universe is a function of the
  declared geometry alone. 488 calls → 4.
* `placement_map(...)` by (key, geometry, region, taint, n): measured **488 calls but only 79 distinct
  taint masks**, so the cache is hit 6×.
* `block_universe(ll_shape)` — needed because the cache wrapper compared the caller's universe against
  a fresh one on every call; without this the first version of the change was **slower** (corner 40%:
  159 → 182 s). No caller mutates the universe, so caching it is safe.

Measured after: corner 25% **127.7 → 85 s**, corner 40% **159 → 144 s**, symmetric 5% **160 → 148 s**,
clean round trip **0.5 → 0.3 s**. `embed.py` and `extract.py` self-tests pass with unchanged verdicts.

**Still open, and the bulk of what is left:** (a) the polar decoder is still 58% of the remaining time
— vectorise the SCL decoder over the L paths (10–50×, must stay bit-identical); (b) the search still
exact-tests all 81 fine offsets for every decoy candidate — prescore and exact-test ~3 instead (~27×).
(c) transform once per scale rather than per offset.

**This is a prerequisite for the official crop row of the G1 matrix** — 50 crop marks at ~150 s each
is over two hours for a row that should take minutes.

## 6. Why the encoder is untouched (and why non-crop recovery is untouched too)

Two independent reasons, one structural and one measured.

**Structural.** `mark` reads its own output back with `coverage=None`, so `place_taint == erase_taint`
and every path is the pre-change path. Measured: capacity `[371, 374, 368, 370]` unchanged, round-trip
BER `[0.0, 0.0, 0.0, 0.0]`, `max |change| outside ROI` 16, pixel-support rule violations 0. The
`embed.py` self-test passes.

**Measured, for everything that is not a crop.** `coverage_map` follows the resampler's own rule — a
source coordinate one pixel outside still clamps to a real border sample, so only coordinates more
than a pixel outside are uncovered — and that makes the mask **exactly 1.0 on every non-crop
condition**, including the resize cases with a half-pixel phase:

| condition | covered | tainted blocks |
|---|---|---|
| identity | 1.000000 | 0 |
| resize 0.5x | 1.000000 | 0 |
| resize 0.75x (beta −0.25) | 1.000000 | 0 |
| resize 1.5x | 1.000000 | 0 |
| resize 2.0x | 1.000000 | 0 |
| corner crop 40% | 0.360876 | 4800 of 7500 |
| symmetric crop 5% | 0.812627 | 1470 of 7500 |

With an all-true mask the ROI statistics see every pixel and `undercovered_blocks` adds nothing, so
`place_taint == erase_taint == blocked_blocks()` — the old code, bit for bit. (The first version of
the mask used a strict inside-the-image test, which reported row 0 of a phased resize as missing and
gave 0.998542; that is why the tolerance is there.) Checked against the previous revision on
3 covers × 8 non-crop conditions: **0 verdict changes**.

The `extract.py` self-test passes with crop 25% now PASS; the mis-locked-pilot regression test still
passes.
