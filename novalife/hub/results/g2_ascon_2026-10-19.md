## What was wrong before

`vivado/ip_repo/ascon_core/ascon128_aead.v` carried the name `ascon128_aead` but implemented **no
Ascon**: its "round" only XORed the round constant into `S[2]` — there was no 5-bit S-box and no
linear diffusion layer. It was not a cipher. Its testbench printed `SUCCESSFUL` unconditionally and
compared nothing, and `tools/tag_reference/ascon_primitives.py`'s docstring asserted the PL core was
"real Ascon-128"; that assertion was **false** (it has since been corrected). This file replaces the
stub with the real permutation and an AEAD framing FSM.

## The reference (the contract)

`tools/tag_reference/ascon_primitives.ascon_aead_encrypt` — Ascon-AEAD128, NIST SP 800-232
(128-bit key/nonce/tag, 64-bit rate, p^12 init/final, p^6 per block, IV `0x80400c06…`, round
constants `0xF0…0x4B`). It self-checks against the official LWC known-answer vectors:
`ascon_primitives.selftest() == True`.

Vectors: `tools/tag_reference/vectors/gen_ascon_vectors.py` →
`ascon_meta.mem`, `ascon_ad.mem`, `ascon_pt.mem`, `ascon_ct.mem`, `ascon_params.vh`,
`ascon_vectors.json` (19 cases: the 17 official KATs + the hub **MAC** and **keystream** paths).

## Verification (simulation, Icarus)

```
vivado/scripts/run_sim.sh ascon_core ascon128_aead_tb.v
  -> ascon128_aead_tb: PASS (19 vectors, bit-exact vs ascon_primitives)
```

Every one of the 19 ciphertexts and tags matches the reference byte for byte. Two of the cases are
the paths the hub actually uses:

| case | construction | checked against |
|---|---|---|
| `product_mac` | empty plaintext, AD = `MAC_DOMAIN \|\| len \|\| header` | `tag_block.mac_truncated` (asserted in the generator) |
| `product_keystream` | plaintext = 24 zero bytes, AD = a domain string | `ascon_primitives.keystream` |

**Mutation-tested** (the testbench must catch real defects, not just pass):
- dropping one term of the S[0] linear layer (`ror(x,28)`) → **58 errors**;
- `DSEP` as `0x01 << 56` instead of `0x01 << 0` → **35 errors**.

### Byte-order traps found while making it bit-exact (all in the reference, not the spec's intuition)

1. `DSEP()` is `SETBYTE(0x01, pos=7)` = `0x01 << 0` (the **least** significant byte), not `<< 56`.
2. The **full** plaintext block is loaded **big-endian** (`_load`, line 166) while the **final partial**
   plaintext block is loaded **little-endian** (`"little"`, line 171). The core keeps two accumulators
   for this reason. (This is a quirk of the reference; it is the frozen contract.)
3. A partial AD block is big-endian and left-aligned (`_load` of a zero-padded block) while a partial
   plaintext block is little-endian.

- Worst path: `pt_cnt` → `S[0]` (the plaintext-load shift), +3.210 ns slack.
- `Bonded IOB = 479 > 100` is an artifact of synthesising the core as top (wide ports become device
  IOs); inside a block design they are internal.
- Throughput: one permutation round per clock; AEAD costs `12 + 6·n_blocks + 12` cycles + framing.

## Interface (changed — nothing integrates this core yet)

Byte-stream AEAD with a valid/ready handshake (`ad_ready`, `pt_ready`), so no byte is dropped while a
permutation runs:

```
pulse start with key/nonce held
  -> ad_data/ad_valid while ad_ready, then pulse ad_done
  -> pt_data/pt_valid while pt_ready, then pulse pt_done
  -> ct_data/ct_bytes/ct_valid (big-endian word), then tag_out with done
```
